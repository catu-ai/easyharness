## Goal

Prepare the dedicated stable `easyharness v0.6.0` release candidate after four
successful RC dogfood releases and the final bounded-discovery correction. The
tracked candidate changes the bare repository version from `0.6.0-rc.4` to
`0.6.0`, proves the existing VERSION-driven automation is release-ready, and
publishes a narrow ready PR for explicit merge approval.

After that release PR is separately approved and landed, complete the existing
release checklist: verify the stable tag, GitHub Release assets, Homebrew tap
promotion and upgrade/test path, then close the v0.6.0 umbrella/milestone only
when publication succeeds.

### Decisions and Constraints

- This is the selected stable minor release for milestone `v0.6.0`, not another
  prerelease or a patch release.
- The release candidate is a dedicated narrow VERSION change plus its tracked
  plan; feature, workflow, prompt, documentation, and release-automation changes
  are excluded.
- `VERSION` stores the bare stable value `0.6.0`; automation is expected to
  create tag `v0.6.0` and a non-prerelease GitHub Release.
- The current `main` head after PR #299 is the intended stable source. Do not
  reopen RC scope or include unrelated work that lands later without an
  explicit sync/review decision.
- Use the full release validation profile before publish. Green post-merge
  automation does not substitute for candidate validation.
- Stop the execution workflow at `await_merge`; the release PR requires its own
  explicit human merge approval. Post-merge publication verification belongs
  to `harness-land` bookkeeping.
- Keep issue #293 and milestone `v0.6.0` open until the stable Release and
  Homebrew verification succeed; then record the durable result and close them.

## Scope

### In Scope

- Set the repository's bare version to stable `0.6.0` in a dedicated release
  candidate.
- Run the full release-ready validation and a local stable release packaging
  check from the fixed candidate.
- Independently review, archive, publish, and record current PR/CI/sync evidence
  through `await_merge`.
- After later explicit merge approval, verify VERSION-driven tag/release
  automation, all platform archives and `SHA256SUMS`, stable Homebrew formula
  publication, upgrade, binary metadata, and `brew test` before closing the
  release umbrella and milestone.

### Out of Scope

- Any product, workflow, prompt, schema, UI, or release-automation change.
- Another RC, a `0.6.x` patch, or beginning `v0.7.0` goal-oriented work.
- Republishing or modifying previous RC releases.
- Closing #293 or milestone `v0.6.0` before the stable release is successfully
  published and verified.

## Acceptance Criteria

- [x] The candidate contains the exact bare stable version `0.6.0`, with no

- [x] The release-ready validation profile and local `v0.6.0` packaging check

      metadata, checksum, and ordinary repository coverage.
