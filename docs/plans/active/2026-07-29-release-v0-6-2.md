# Release easyharness v0.6.2 for coordinated workflow dogfood

## Goal

Prepare the dedicated `easyharness v0.6.2` patch release candidate so the team
can dogfood the coordinated root/subplan workflow merged in PR #304. The
candidate changes only the repository version and tracked release plan, proves
the existing VERSION-driven release path, and publishes a narrow PR for
separate merge approval.

After that release PR is approved and landed, verify the generated tag, GitHub
Release assets, checksums, binary metadata, and Homebrew publication before
completing post-merge bookkeeping.

### Decisions and Constraints

- This is an explicit dogfood patch on the existing v0.6 line. It does not
  claim or replace the separate goal-oriented `v0.7.0` milestone promise.
- `VERSION` stores the bare value `0.6.2`; automation is expected to create
  stable tag `v0.6.2` and a non-prerelease GitHub Release.
- The release candidate contains only the version transition and tracked plan
  lifecycle changes. Product, workflow, schema, UI, and release-automation
  changes are excluded.
- Coordinated workflow dogfood is CLI-first. Coordinated UI remains unsupported
  in this release; the existing UI guarantee remains single-plan only.
- Run the full release-ready validation profile and local packaging check from
  the fixed candidate before publish.
- Stop at `await_merge` for explicit human approval. Tag, asset, and Homebrew
  verification belongs to post-merge `harness-land` bookkeeping.

## Scope

### In Scope

- Set the repository's bare version from `0.6.1` to `0.6.2`.
- Run the complete release-ready validation and local `v0.6.2` packaging
  verification.
- Independently review, archive, publish, and record current PR/CI/sync
  evidence through `await_merge`.
- After later merge approval, verify VERSION-driven release automation,
  platform archives, `SHA256SUMS`, stable Homebrew formula publication, and
  released binary metadata before completing land.

### Out of Scope

- Any additional product, documentation, workflow, prompt, schema, UI, or
  release-automation change.
- Reassigning, reshaping, or releasing the existing `v0.7.0` milestone.
- Adding coordinated UI or advanced coordinated orchestration.
- Rewriting or republishing previous v0.6.x artifacts.

## Acceptance Criteria

- [ ] The candidate contains the exact bare version `0.6.2`, with no unrelated
      product or release-automation change.
- [ ] `scripts/validate-release` and a local `v0.6.2` packaging check pass,
      including installer, archive, checksums, platform set, and binary version
      metadata.

## Review Focus

- Confirm `0.6.2` is monotonic from `0.6.1`, is classified as a stable patch,
  and maps to tag `v0.6.2`.
- Confirm the candidate is a dedicated release diff and does not bundle
  unrelated behavior or release-automation changes.
- Confirm validation exercises the artifacts dogfood users will install,
  rather than only ordinary unit tests.
- Confirm coordinated UI remains explicitly unsupported and the release does
  not imply completion of the unrelated `v0.7.0` promise.
- Confirm the separate merge-approval boundary and post-merge publication
  verification remain intact.

  dedicated VERSION transition based on current `main`.

  four platform archives plus `SHA256SUMS`, stable Homebrew publication, and
  matching released binary metadata before completing land.
